# NovelStudio — Plan & Workflow
**เว็บแอพแต่งนิยายหลายโมดูล พร้อมผู้ช่วย AI (OpenRouter)**
เวอร์ชันเอกสาร: 1.0 — ยังไม่เขียนโค้ด เอกสารนี้คือสเปกสำหรับสร้างจริง

---

## 1. ภาพรวมและเป้าหมาย

**ปัญหาที่แก้:**
- ไอเดียมาไว แต่พอเขียนจริงเรื่องไม่ต่อเนื่อง ชื่อคน/สถานที่/สกิลหลุด โลกทัศน์เละ
- เครื่องมือสำเร็จรูป (NovelCrafter ฯลฯ) ซับซ้อนเกิน ตั้งค่านานจนหมดสนุก
- AI แบบ chat ธรรมดาไม่มีบริบทของเรื่อง ทำให้ผลลัพธ์ไม่เข้ากับโลกที่สร้างไว้

**หลักการออกแบบ (Design Principles):**
1. **Idea-first** — เปิดแอพแล้วเขียนได้ใน 3 คลิก ไม่บังคับกรอกอะไรก่อน
2. **Codex คือหัวใจ** — ข้อมูลโลกทั้งหมดเก็บที่เดียว AI ทุกฟีเจอร์ดึงจากที่นี่
3. **ผู้เขียนคุม AI เสริม** — AI ไม่เขียนแทน แต่ต่อ/เกลา/เช็ค/คิดชื่อให้ ตามคำสั่ง
4. **บริบทเลือกได้** — ผู้ใช้ติ๊กเลือกว่าจะส่งข้อมูลอะไรให้ AI (+ โหมด Auto)
5. **ไม่มี build step** — เปิดใช้ได้เลยทั้งคอมและมือถือ ไม่ต้องติดตั้ง

## 2. Tech Stack และสถาปัตยกรรม

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Frontend | Vanilla JS (ES Modules) + HTML + CSS | ไม่มี build step, แก้ไขง่าย, รันได้บน Termux/มือถือ/คอม — แนวเดียวกับ NovelForge |
| โครงสร้าง | Multi-file modular — 1 โมดูล = 1 ไฟล์ JS | แยกความรับผิดชอบชัด แก้ทีละส่วนไม่พังทั้งแอพ |
| Storage หลัก | **IndexedDB** (ผ่าน wrapper เล็กๆ เขียนเอง) | localStorage จำกัด ~5MB ไม่พอสำหรับนิยายหลายเรื่องหลายร้อยตอน |
| Storage รอง | localStorage | เก็บ settings, API key, ธีม, โปรเจกต์ล่าสุด |
| Backup | Export/Import JSON (ทั้งแอพ หรือรายโปรเจกต์) | ย้ายข้ามเครื่อง คอม↔มือถือ ด้วยไฟล์เดียว |
| AI | OpenRouter API (`/chat/completions`) เรียกตรงจาก browser | รูปแบบเดียวกับที่ใช้ใน NovelTrans/NovelForge |
| การรัน | เปิดผ่าน static server (`python -m http.server` หรือ `npx serve`) | ES Modules ต้องรันผ่าน http:// ไม่ใช่ file:// |

> **หมายเหตุ:** ถ้าอนาคตอยากซิงค์คอม↔มือถืออัตโนมัติ ค่อยเพิ่ม Supabase sync เป็น Phase เสริม (แม็กมีโปรเจกต์ Supabase อยู่แล้ว) — schema ในเอกสารนี้ออกแบบเผื่อไว้แล้ว (ทุก record มี `id` + `updatedAt`)

## 4. Data Schema (IndexedDB)

### Store: `projects`
```json
{
  "id": "prj_xxx",
  "title": "ดาบเทพจอมมาร",
  "genre": "murim",            // fantasy | murim | romance | custom
  "customGenrePrompt": "",      // ใช้เมื่อ genre = custom
  "synopsis": "",
  "createdAt": 0, "updatedAt": 0
}
```

### Store: `chapters`
```json
{
  "id": "ch_xxx",
  "projectId": "prj_xxx",
  "number": 12,
  "title": "ศึกหุบเขามังกร",
  "content": "...",             // เนื้อหาเต็ม
  "summary": "...",             // สรุปโดย AI (M6) — ว่างได้
  "status": "draft",            // draft | done | published
  "wordCount": 3200,
  "updatedAt": 0
}
```

### Store: `codex`
```json
{
  "id": "cdx_xxx",
  "projectId": "prj_xxx",
  "type": "character",          // character | place | skill | item | rule | other
  "name": "อีซอจุน",
  "aliases": ["จอมดาบเงา"],   // ชื่อเรียกอื่น — ใช้ตอน auto-detect
  "description": "ลูกศิษย์คนโตสำนัก... นิสัยเย็นชา ใช้ดาบสายลม",
  "tags": ["ตัวเอก", "สำนักเมฆขาว"],
  "pinned": false,              // ปักหมุด = ส่งเข้า AI ทุกครั้ง
  "updatedAt": 0
}
```

### Store: `settings` (localStorage)
```json
{
  "apiKey": "sk-or-...",
  "model": "anthropic/claude-sonnet-4",
  "fallbackModel": "google/gemini-flash",
  "theme": "dark",
  "lastProjectId": "prj_xxx",
  "maxContextChars": 8000
}
```

## 5. สเปกรายโมดูล

### M1 — Projects (จัดการโปรเจกต์)
- หน้าแรกของแอพ: การ์ดโปรเจกต์ทั้งหมด + ปุ่ม "+ เรื่องใหม่"
- สร้างเรื่องใหม่ = กรอกแค่ **ชื่อเรื่อง + เลือกแนว** แล้วเข้า Editor ทันที (synopsis เติมทีหลังได้)
- สลับโปรเจกต์ได้จาก dropdown บน header ทุกหน้า
- ลบ/duplicate/export รายโปรเจกต์

### M2 — Editor (เขียนรายตอน)
- Sidebar ซ้าย: รายชื่อตอน (ลากเรียงได้, แสดง status + จำนวนคำ)
- กลาง: textarea ใหญ่ ฟอนต์อ่านสบาย ปรับขนาดได้ **autosave ทุก 2 วินาที** (debounce)
- มือถือ: sidebar พับเป็น drawer, แผง AI พับเป็น bottom sheet
- ตัวช่วยในหน้า: นับคำสด, โหมดเขียนโล่ง (ซ่อนทุกอย่างเหลือแต่ข้อความ)
- **ไฮไลต์ชื่อจาก Codex** ในเนื้อหา (ขีดเส้นใต้จางๆ) — แตะแล้วเห็นข้อมูลย่อ ช่วยกันเขียนชื่อผิด

### M3 — Codex (ฐานข้อมูลโลก)
- แท็บแยกตาม type: ตัวละคร / สถานที่ / สกิล-ไอเทม / กฎของโลก / อื่นๆ
- เพิ่มรายการเร็ว: ชื่อ + คำอธิบาย จบ (ช่องอื่น optional)
- **Quick-add จาก Editor:** ลากคลุมชื่อในเนื้อหา → คลิกขวา/กดค้าง → "เพิ่มเข้า Codex" (AI ช่วยร่างคำอธิบายจากบริบทรอบๆ ให้)
- ปักหมุด (pin) รายการสำคัญ = ถูกส่งให้ AI ทุกครั้ง
- ค้นหา + filter ด้วย tag

### M4 — AI Assist (แผงข้าง Editor)
5 ปุ่มคำสั่ง แต่ละอันเปิด panel ผลลัพธ์ → ผู้ใช้กด "แทรก" / "แทนที่" / "ลองใหม่" / "ทิ้ง"

| ปุ่ม | Input ที่ส่ง | ผลลัพธ์ |
|---|---|---|
| ✍️ เขียนต่อ | เนื้อหาท้ายตอน ~2,000 ตัวอักษร + context | ย่อหน้าถัดไป 1-3 ย่อหน้า (ปรับความยาวได้) |
| ✨ เกลาสำนวน | ข้อความที่ลากเลือก + โทนที่ต้องการ | ข้อความเวอร์ชันเกลาแล้ว แสดงเทียบก่อน/หลัง |
| 🏷️ คิดชื่อ | ประเภท (คน/ที่/สกิล) + คำใบ้ + genre + Codex | รายชื่อ 8-10 ตัวเลือก พร้อมความหมายสั้นๆ กด + เพิ่มเข้า Codex ได้เลย |
| 🔍 เช็คต่อเนื่อง | ตอนปัจจุบัน + Codex + สรุปตอนก่อนๆ | รายการจุดขัดแย้ง (ชื่อผิด/ข้อมูลชนกับตอนเก่า/ตรรกะหลุด) พร้อมระบุตำแหน่ง |
| 💡 ระดมไอเดีย | สรุปเรื่องถึงปัจจุบัน + โจทย์ที่พิมพ์ | 3-5 ทางเลือกพล็อต พร้อมข้อดี-ข้อเสียสั้นๆ |

- ทุกคำสั่งใช้ **streaming** — เห็นข้อความไหลออกทันที ไม่ต้องรอจบ
- มีช่อง "คำสั่งเพิ่มเติม" ให้พิมพ์กำกับได้ทุก action (เช่น "เน้นบรรยากาศหม่นๆ")

### M5 — Context Picker (หัวใจของความต่อเนื่อง)
ก่อนยิง AI ทุกครั้ง แถบ context ด้านบนแผง AI แสดงว่าจะส่งอะไรไปบ้าง:

- **Auto-detect:** สแกนเนื้อหาตอนปัจจุบัน หาชื่อ/aliases ที่ตรงกับ Codex → ติ๊กให้อัตโนมัติ
- **Pinned:** รายการที่ปักหมุดติ๊กเสมอ
- **Manual:** กดเปิด modal เลือกเพิ่ม/เอาออกเองได้ทุกรายการ
- แสดง **ตัวนับขนาด context** (ตัวอักษร/ประมาณ token) — เกิน budget แล้วเตือนให้ตัด
- จำการเลือกไว้ต่อตอน ไม่ต้องติ๊กใหม่ทุกครั้ง

### M6 — Continuity Memory (ความจำเรื่อง)
- จบตอน กด "สรุปตอนนี้" → AI สรุป 3-5 บรรทัด (เหตุการณ์สำคัญ, ตัวละครที่ปรากฏ, ปมค้าง) เก็บใน `chapter.summary` แก้มือได้
- เวลาใช้ AI Assist: ระบบแนบ **สรุปของ N ตอนล่าสุด** (default 5 ตอน, ปรับได้) ให้อัตโนมัติ
- มีหน้า "ไทม์ไลน์เรื่อง" — อ่านสรุปทุกตอนเรียงกัน scan เร็วๆ ก่อนเขียนตอนใหม่
- เตือนเมื่อมีตอนที่ยังไม่สรุป (badge บนรายชื่อตอน)

### M7 — Settings
- API key (เก็บ localStorage เท่านั้น ไม่ออกนอกเครื่องยกเว้นส่งหา OpenRouter)
- เลือกโมเดลหลัก + โมเดลสำรอง (fallback อัตโนมัติเมื่อ error/หมดโควตา)
- แก้ system prompt ต่อแนวเรื่องได้ (advanced)
- สลับธีมมืด/สว่าง, ขนาดฟอนต์ editor
- Export/Import JSON (ทั้งแอพ / รายโปรเจกต์), ปุ่มล้างข้อมูล

## 6. AI Layer — สถาปัตยกรรม Prompt

### 6.1 โครง prompt ทุกคำสั่ง (ประกอบ 4 ชั้น)
```
[1] SYSTEM: บทบาท "ผู้ช่วยนักเขียนนิยายไทย" + กฎภาษา
    + genre prompt ตามแนวเรื่อง (fantasy/murim/romance/custom)
[2] WORLD CONTEXT: รายการ Codex ที่ถูกเลือกจาก M5 (จัดรูปแบบกระชับ)
[3] STORY MEMORY: สรุป N ตอนล่าสุดจาก M6 + synopsis
[4] TASK: คำสั่งเฉพาะ action + เนื้อหาที่เกี่ยว + คำกำกับจากผู้ใช้
```

### 6.2 Genre prompts (แยกไฟล์ `genres.js` — แก้ง่าย เพิ่มแนวใหม่ง่าย)
- **fantasy:** ศัพท์แฟนตาซี/ระบบ/สเตตัส, ชื่อสไตล์ตะวันตก-เกาหลี, โทนผจญภัย
- **murim:** ศัพท์ยุทธภพ กระบวนท่า ลมปราณ, ชื่อจีนถอดเสียงไทยตามธรรมเนียมนิยายกำลังภายใน, สำนวนโบราณ
- **romance:** เน้นอารมณ์ บทสนทนา ความสัมพันธ์, บรรยาย internal monologue
- **custom:** ผู้ใช้เขียนเอง

> โครงสร้างนี้ตั้งใจให้เป็นแบบเดียวกับ modular genre prompts ใน Novel-Tran-Pro — ถ้าอยากพอร์ต/แชร์กฎภาษาไทย (เช่น กฎ ครับ/ค่ะ, ระดับภาษา) ทำได้ทันที

### 6.3 กติกาสำคัญของ AI Layer
- **Context budget:** จำกัดชั้น [2]+[3] รวมไม่เกิน `maxContextChars` (default 8,000 ตัวอักษร) — Codex ที่เลือกเกินให้ตัดตามลำดับ: pinned > auto-detect > manual เก่าสุด
- **Streaming ทุกคำสั่ง** ยกเว้น "เช็คต่อเนื่อง" (ขอ JSON — ต้องรอครบ)
- **เช็คต่อเนื่อง** สั่งให้ตอบเป็น JSON: `[{type, location, detail, suggestion}]` → render เป็นรายการคลิกไปยังตำแหน่งในตอนได้
- Retry อัตโนมัติ 2 ครั้งเมื่อ network error → สลับ fallback model → แจ้งผู้ใช้
- แสดงค่าใช้จ่ายโดยประมาณต่อคำสั่ง (จาก usage ที่ OpenRouter ตอบกลับ)

## 7. User Workflows หลัก

### W1 — เริ่มเรื่องใหม่ (เร็วสุด: ~30 วินาที)
1. หน้า Projects → "+ เรื่องใหม่" → ใส่ชื่อ + เลือกแนว → **เข้า Editor ทันที**
2. เขียนได้เลย — Codex ค่อยเติมระหว่างทางด้วย Quick-add
3. (ทางเลือก) กด 💡 ระดมไอเดีย ให้ AI ช่วยตีกรอบพล็อตจากไอเดียดิบที่พิมพ์

### W2 — เซสชันเขียนประจำวัน
1. เปิดแอพ → เด้งเข้าโปรเจกต์+ตอนล่าสุดอัตโนมัติ
2. อ่านสรุปตอนก่อนหน้า (แสดงพับไว้บนหัวตอน) → เขียนต่อ
3. ตัน → ✍️ เขียนต่อ (Auto-detect เลือกบริบทให้แล้ว) → อ่าน → แทรก/แก้/ทิ้ง
4. เจอชื่อใหม่ที่เพิ่งคิด → ลากคลุม → เพิ่มเข้า Codex
5. จบตอน → 🔍 เช็คต่อเนื่อง → แก้ตามรายการ → "สรุปตอนนี้" → เปลี่ยน status เป็น done

### W3 — คิดชื่อให้เข้ากับโลก
1. กด 🏷️ → เลือกประเภท → พิมพ์คำใบ้ ("สกิลดาบสายน้ำแข็ง ของตัวร้าย")
2. AI เสนอ 8-10 ชื่อ อิงแนวเรื่อง + ชื่อที่มีอยู่แล้วใน Codex (กันซ้ำ/กันโทนหลุด)
3. กด + ข้างชื่อที่ชอบ → เข้า Codex ทันที พร้อมคำอธิบายร่าง

### W4 — ย้ายเครื่อง / สำรองข้อมูล
1. Settings → Export ทั้งแอพ → ได้ไฟล์ `novelstudio-backup-YYYYMMDD.json`
2. ส่งเข้าอีกเครื่อง (LINE/Drive/สาย) → Import → เลือก merge หรือ replace

### ธีม
- CSS variables ชุดเดียว สลับ dark/light ด้วย `data-theme` บน `<html>`
- Dark เป็น default (เขียนกลางคืนถนอมตา), จำค่าที่เลือกไว้
- ฟอนต์เนื้อหา: ฟอนต์ไทยอ่านยาวสบาย (เช่น Sarabun/Bai Jamjuree จาก Google Fonts พร้อม fallback ระบบ), UI ใช้ฟอนต์ระบบ
- แตะง่ายบนมือถือ: ปุ่มขั้นต่ำ 44px, autosave กันมือถือดับ

## 9. Roadmap การพัฒนา

| Phase | ขอบเขต | ผลลัพธ์ที่ใช้ได้จริง |
|---|---|---|
| **1 — Core** | โครงแอพ, db.js, M1 Projects, M2 Editor (autosave, รายตอน), M7 Settings ขั้นต่ำ (key/โมเดล/ธีม), Export/Import | เขียนนิยายเก็บในเครื่องได้สมบูรณ์ แม้ไม่มี AI |
| **2 — AI พื้นฐาน** | openrouter.js (stream/retry/fallback), M4: เขียนต่อ + เกลาสำนวน, genre prompts | ผู้ช่วยเขียนใช้งานได้จริง |
| **3 — Codex + Context** | M3 เต็มรูปแบบ, Quick-add, M5 Context Picker (auto-detect/pin/manual/budget), ไฮไลต์ชื่อใน Editor | AI รู้จักโลกของเรื่อง — จุดที่เหนือกว่า chat ธรรมดา |
| **4 — Continuity** | M6 สรุปตอน + ไทม์ไลน์, M4: เช็คต่อเนื่อง + คิดชื่อ + ระดมไอเดีย | ครบ 5 ฟีเจอร์ AI ระบบกันเรื่องหลุดทำงานเต็มวง |
| **5 — Polish** | mobile UX เก็บงาน, ค่าใช้จ่าย/usage, คีย์ลัด, โหมดเขียนโล่ง | พร้อมใช้ทำงานจริงทุกวัน |
| *(เสริม)* | Supabase sync, export EPUB/txt สำหรับลงเว็บขาย | ต่อยอดตามการใช้งานจริง |

แต่ละ Phase จบแล้ว**ใช้งานได้จริงทันที** ไม่ต้องรอครบทุก Phase

## 10. ความเสี่ยงและข้อควรระวัง

| ประเด็น | แนวรับมือ |
|---|---|
| API key อยู่ใน browser | เก็บเฉพาะ localStorage เครื่องตัวเอง, เตือนไม่ให้ deploy ขึ้นเว็บสาธารณะทั้ง key |
| Context ใหญ่ = แพง | budget + ตัวนับใน M5, ใช้สรุปตอน (M6) แทนเนื้อเต็ม, เลือกโมเดลถูกสำหรับงานเบา (สรุป/คิดชื่อ) |
| ข้อมูลหายเพราะเคลียร์ browser | เตือน export เป็นระยะ (badge เมื่อไม่ได้ backup เกิน 7 วัน) |
| AI เขียนชื่อเพี้ยนแม้มี Codex | ใส่กฎใน system prompt: "ใช้ชื่อตาม WORLD CONTEXT เท่านั้น ห้ามแปลงหรือสะกดใหม่" + เช็คต่อเนื่องเป็นด่านสุดท้าย |
| ES Modules เปิดจาก file:// ไม่ได้ | README ระบุวิธีรัน 1 บรรทัด ทั้งคอม (`python -m http.server`) และ Termux |
